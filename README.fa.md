# srvmon — مانیتورینگ متمرکز سرورها

**[🇬🇧 English README](README.md)**

یک سیستم مانیتورینگ سبک با همان ظاهر صفحه نمای کلی پنل 3x-ui: همان کارت‌های
وضعیت، نمودارهای لحظه‌ای، کارت پهنای باند و نوار سیستم — اما برای مجموعه‌ای از
سرورها به‌جای یک ماشین، و بدون هیچ بخشی از پنل فیلترشکن.

یک **hub** (سرور مرکزی) داشبورد را سرو می‌کند. روی هر سرور دیگر یک **agent**
سبک اجرا می‌شود که متریک‌ها را روی HTTPS به مرکز می‌فرستد. ایجنت فقط اتصال
**خروجی** می‌زند، پس پشت NAT و فایروال بسته هم کار می‌کند.

</div>

```
  سرور A ──┐
  سرور B ──┼── push روی HTTPS با توکن (هر ۲ ثانیه) ──▶  hub  ──▶  داشبورد
  سرور C ──┘                                            │
                                                        └──▶  هشدار تلگرام
```

## شروع سریع

روی سرور مرکزی:

</div>

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/lalash/srvmon/main/scripts/install-hub.sh)
```

<div dir="rtl">

خودش هرچه لازم دارد می‌پرسد — نوع گواهی، دامنه، پورت، رمز ادمین — بعد Go را
نصب می‌کند، بیلد می‌گیرد، گواهی SSL را می‌گیرد و سرویس را بالا می‌آورد:

</div>

```
? How should the dashboard be served?
  1. HTTPS with a free Let's Encrypt certificate for a domain (auto-renews)
  2. HTTPS for this server's IP address — no domain needed (~6-day cert, auto-renews)
  3. HTTPS with certificate files you already have
  4. Plain HTTP — only safe behind a reverse proxy or on a private network
? Choose [1]: 1
? Domain name (e.g. monitor.example.com): monitor.example.com
? Port for the dashboard [443]:
? Set the admin password yourself? (otherwise one is generated) [y/N]:
? ufw is active — open port 443? [Y/n]:
```

<div dir="rtl">

دامنه ندارید؟ گزینه **۲** را بزنید. Let's Encrypt برای آی‌پی خالی هم گواهی
صادر می‌کند (پروفایل کوتاه‌مدت)، پس HTTPS واقعی بدون اخطار مرورگر می‌گیرید
بدون اینکه لازم باشد دامنه بخرید.

</div>

<div dir="rtl">

آدرسی که چاپ می‌شود را باز کنید، با رمز تولیدشده وارد شوید، بعد
**سرورها ← افزودن سرور**. یک دستور تک‌خطی می‌گیرید که روی هر ماشینی که
می‌خواهید مانیتور شود اجرا می‌کنید:

</div>

```bash
sudo bash <(curl -fsSL https://monitor.example.com/install-agent.sh) --hub https://monitor.example.com --token <token> --name berlin-1
```

<div dir="rtl">

آن سرور ظرف چند ثانیه روی داشبورد ظاهر می‌شود.

## چه چیزهایی جمع می‌کند

برای هر سرور، هر دو ثانیه: مصرف پردازنده (با هموارسازی EMA)، حافظه، سواپ،
فضای دیسک، سرعت آپلود و دانلود و ترافیک تجمعی، تعداد اتصالات TCP و UDP،
میانگین بار سیستم، تعداد پروسه‌ها، مدت روشن بودن، IPv4/IPv6 عمومی، سیستم‌عامل،
کرنل، معماری و مدل پردازنده.

## امکانات

- **نمای کلی ناوگان** — کارت‌های میانگین پردازنده/حافظه/فضا، پهنای باند کل، و
  یک کارت برای هر سرور با نوارهای زنده و نمودار کوچک پردازنده.
- **صفحه اختصاصی هر سرور** — چیدمان کامل نمای کلی: کارت‌های پردازنده / حافظه /
  سواپ / فضا، نمودار پهنای باند با راهنمای شناور، نمودار اتصالات، و نوار سیستم.
  انتخاب بازه: زنده، ۱ ساعت، ۶ ساعت، ۲۴ ساعت، ۷ روز، ۳۰ روز.
- **تاریخچه** — هر ۳۰ ثانیه یک نقطه برای هر سرور ذخیره می‌شود، به‌طور پیش‌فرض
  ۸ روز نگه داشته می‌شود و هنگام نمایش در باکت‌ها میانگین‌گیری می‌شود.
- **هشدارها** — آستانه پردازنده / حافظه / دیسک همراه با شمارنده «تداوم» برای
  فیلتر کردن نوسان‌های لحظه‌ای، به‌علاوه تشخیص آفلاین شدن. ارسال به تلگرام و
  ثبت در گزارش رویدادها.
- **حساب کاربری** — ورود با کوکی نشست، رمز با bcrypt، محدودیت نرخ تلاش ورود.
- **رابط دوزبانه** — فارسی (راست‌به‌چپ) و انگلیسی، تم روشن و تیره.

## نصب سرور مرکزی

اسکریپت نصب همه‌چیز را خودش انجام می‌دهد: نصب Go، دریافت سورس در `/opt/srvmon`،
بیلد hub و ایجنت‌های لینوکس (amd64/arm64/arm)، گرفتن گواهی SSL، نصب یونیت
systemd و باز کردن پورت در فایروال. در اولین اجرا یک رمز ادمین تولید و چاپ
می‌کند — آن خط تنها جایی است که این رمز دیده می‌شود.

هر سؤالی را می‌شود از قبل با گزینه خط فرمان جواب داد؛ اگر همه را بدهید (یا `-y`
بزنید) هیچ سؤالی نمی‌پرسد.

| گزینه | پیش‌فرض | کاربرد |
| --- | --- | --- |
| `--port N` | با SSL برابر ۴۴۳، وگرنه ۸۰۸۰ | پورتی که داشبورد روی آن اجرا می‌شود |
| `--ssl domain\|ip\|files\|none` | پرسیده می‌شود | نوع گواهی |
| `--domain NAME` | پرسیده می‌شود | دامنه برای حالت `domain` |
| `--server-ip ADDR` | تشخیص خودکار | آی‌پی عمومی برای حالت `ip` |
| `--cert` / `--key` | پرسیده می‌شود | مسیر فایل‌ها برای حالت `files` |
| `--acme-port N` | `80` | پورتی که acme.sh هنگام اعتبارسنجی می‌گیرد |
| `--admin-user` | `admin` | نام کاربر اول |
| `--admin-password` | تولید خودکار | رمز کاربر اول |
| `--base-url URL` | خودکار | جایگزینی آدرسی که در دستور نصب ایجنت‌ها می‌آید |
| `--data-dir DIR` | `/var/lib/srvmon` | دیتابیس و فایل‌های ایجنت |
| `--open-firewall yes\|no` | پرسیده می‌شود | باز کردن پورت در ufw یا firewalld |
| `--source DIR` | گیت‌هاب | بیلد از یک checkout محلی |
| `-y`, `--yes` | — | قبول همه پیش‌فرض‌ها بدون هیچ سؤالی |
| `--uninstall` | — | حذف سرویس و باینری، دیتابیس دست‌نخورده می‌ماند |

مثلاً به‌صورت کاملاً خودکار:

</div>

```bash
bash install-hub.sh --ssl domain --domain monitor.example.com --port 443 --admin-password 'یک-رمز-خوب' --open-firewall yes
```

<div dir="rtl">

> حتماً `bash <(curl …)` استفاده کنید، نه `curl … | bash`. با پایپ، ورودی
> استاندارد خودِ اسکریپت است، پس هیچ سؤالی نمی‌شود پرسید و هر گزینه‌ای که
> ندهید بی‌صدا مقدار پیش‌فرضش را می‌گیرد. اسکریپت این حالت را تشخیص می‌دهد و
> هشدار می‌دهد.

تنظیمات در `/etc/srvmon/hub.conf` است و یونیت از همان می‌خواند؛ بعد از ویرایش
`systemctl restart srvmon-hub` بزنید. اجرای دوباره اسکریپت نصب، hub را
به‌روزرسانی می‌کند. لاگ: `journalctl -u srvmon-hub -f`.

اگر سرور کمتر از ۱ گیگابایت رم داشته باشد، اسکریپت اول یک فایل swap یک‌گیگی
می‌سازد — وگرنه کامپایلر Go بدون هیچ پیام مفیدی توسط کرنل کشته می‌شود.

### گواهی SSL

اگر گزینه **Let's Encrypt برای دامنه** را انتخاب کنید، `acme.sh` نصب می‌شود،
بررسی می‌شود که رکورد A دامنه واقعاً به همین سرور اشاره کند، گواهی با روش
HTTP-01 روی پورت ۸۰ گرفته می‌شود (حالت standalone، پس نیازی به وب‌سرور نیست) و
یک hook تمدید ثبت می‌شود که گواهی تازه را در `/etc/srvmon/cert/` کپی می‌کند و
hub را ری‌استارت می‌کند. از آن به بعد تمدید کاملاً خودکار است.

گزینه **Let's Encrypt برای آی‌پی** دقیقاً همین مسیر را می‌رود ولی اصلاً دامنه
لازم ندارد. این گواهی‌ها از پروفایل کوتاه‌مدت استفاده می‌کنند و حدود شش روز
اعتبار دارند، پس hook تمدید واقعاً کار می‌کند — با همان cron خودکار acme.sh.

پورت ۸۰ باید هم موقع صدور و هم موقع تمدید از اینترنت قابل دسترس باشد. خود hub
از این پورت استفاده نمی‌کند.

### پشت پروکسی معکوس

اگر ترجیح می‌دهید TLS را در nginx تمام کنید، با `--ssl none` نصب کنید و به آن
پروکسی بزنید. تنها نکته غیربدیهی این است که استریم SSE نباید بافر شود:

</div>

```nginx
location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_buffering off;
    proxy_read_timeout 1h;
}
```

<div dir="rtl">

اگر پروکسی اشتباه تنظیم شود داشبورد خودش به حالت polling برمی‌گردد، پس
کند می‌شود ولی از کار نمی‌افتد.

## اتصال یک سرور جدید

در داشبورد **سرورها ← افزودن سرور** را بزنید. یک توکن و یک دستور آماده
می‌گیرید. روی سروری که می‌خواهید مانیتور شود:

</div>

```bash
sudo bash <(curl -fsSL https://monitor.example.com/install-agent.sh) --hub https://monitor.example.com --token <token> --name berlin-1
```

<div dir="rtl">

این دستور باینری متناسب با معماری سرور را از خود hub می‌گیرد،
`/etc/srvmon/agent.conf` را با دسترسی 600 می‌نویسد، یونیت systemd نصب می‌کند و
اجرا می‌کند.

برای حذف ایجنت `--uninstall` بدهید. لاگ: `journalctl -u srvmon-agent -f`.
اگر گواهی hub خودامضا است، `--insecure` اضافه کنید.

## توسعه محلی

</div>

```bash
make tidy     # حل وابستگی‌ها (نیاز به اینترنت، یک‌بار)
make run      # hub روی :8080 با ./dev.db
```

<div dir="rtl">

بعد یک ایجنت را به آن وصل کنید:

</div>

```bash
go run ./cmd/agent -hub http://localhost:8080 -token <token> -name local -once
```

<div dir="rtl">

دستور `make build` فایل‌های `bin/srvmon-hub` و
`bin/srvmon-agent-linux-{amd64,arm64,arm}` را می‌سازد. داشبورد HTML/CSS/ماژول
ES ساده است که با `embed.FS` داخل باینری جاسازی می‌شود — هیچ مرحله بیلد فرانت
وجود ندارد، پس ویرایش `internal/hub/web/` و ری‌استارت hub کل چرخه توسعه است.

## ساختار پروژه

</div>

```
cmd/hub          باینری سرور مرکزی
cmd/agent        باینری ایجنت هر سرور
internal/metrics جمع‌آوری با gopsutil؛ قرارداد JSON بین ایجنت و مرکز
internal/hub     دیتابیس (SQLite)، API، استریم SSE، هشدارها، داشبورد جاسازی‌شده
internal/hub/web خود داشبورد (html/css/js، بدون مرحله بیلد)
scripts          اسکریپت نصب سرور مرکزی
```

<div dir="rtl">

وابستگی‌ها: `gopsutil` (متریک‌ها)، `modernc.org/sqlite` (SQLite خالص Go، بدون
CGo) و `golang.org/x/crypto` (bcrypt). همین.

## API

دریافت از ایجنت (با توکن bearer):

| متد | مسیر | کاربرد |
| --- | --- | --- |
| POST | `/api/agent/push` | ارسال یک snapshot، دریافت فاصله زمانی مطلوب |

API مدیریت (با کوکی نشست):

| متد | مسیر | کاربرد |
| --- | --- | --- |
| POST | `/api/auth/login` · `/api/auth/logout` | نشست |
| GET | `/api/auth/me` | کاربر فعلی |
| GET | `/api/dashboard` | کل داده داشبورد |
| GET | `/api/stream` | استریم زنده SSE |
| GET/POST | `/api/servers` | فهرست (همراه توکن) / ساخت |
| PATCH/DELETE | `/api/servers/{id}` | تغییر نام / حذف |
| POST | `/api/servers/{id}/token` | صدور توکن جدید |
| GET | `/api/servers/{id}/history?range=1h` | تاریخچه باکت‌بندی‌شده |
| GET/POST | `/api/settings` | تنظیمات هشدار و تلگرام |
| POST | `/api/settings/telegram/test` | ارسال پیام آزمایشی |
| GET | `/api/alerts` | گزارش رویدادهای هشدار |
| POST | `/api/account` | تغییر نام کاربری / رمز |

## نکات امنیتی

- توکن ایجنت‌ها به‌صورت متن ساده در دیتابیس مرکز ذخیره می‌شود تا بشود دستور نصب
  را دوباره نمایش داد؛ پوشه دیتابیس با دسترسی 0750 و فایل تنظیمات ایجنت با 600
  ساخته می‌شود. اگر توکنی لو رفت، از جدول سرورها توکن جدید صادر کنید.
- توکن ربات تلگرام هیچ‌وقت به مرورگر برنمی‌گردد — ذخیره کردن فیلد خالی مقدار
  قبلی را نگه می‌دارد و خط تیره `-` آن را پاک می‌کند.
- درخواست‌های تغییردهنده باید هدر `Origin` هم‌مبدأ داشته باشند، و کوکی نشست
  `HttpOnly` + `SameSite=Lax` است و پشت TLS `Secure` هم می‌شود.
- مسیر `/download/agent/*` عمداً بدون احراز هویت است: ماشینی که در حال نصب است
  هنوز هیچ اعتبارنامه‌ای ندارد و خود باینری ایجنت راز نیست.
